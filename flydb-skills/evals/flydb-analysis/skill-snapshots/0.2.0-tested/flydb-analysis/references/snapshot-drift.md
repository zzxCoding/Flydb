# Schema 快照与漂移

可从 DDL/元数据文件开始，也可使用已配置且获授权的数据库工具。快照是可重复消费的事实材料；完整性限定到来源和声明范围。

## 生成快照

1. 记录材料版本、采集时间、环境、产品/模式/版本及标识符规则。缺失值按 [快照格式](snapshot-format.md) 表达，不猜测当前生产状态。
2. 枚举用户范围内的 table、column、view、procedure、trigger、index、constraint；只处理实际存在或可访问的类型。读取定义与必要元数据；现场工具有分页时持续读取到完成或记录截断。不能因表清单读取完整便宣布过程/触发器完整。
3. 模型将读取的定义整理成 snapshot-format 中的对象与属性，保留每项的来源位置。DDL 按所属产品解释引号和未加引号名称；遇到 ALTER 序列、条件建表或动态 DDL，只合并有明确顺序与条件的部分。不能可靠还原的属性进入 unknownProperties。
4. 写 schema-snapshot.json，执行 `python3 <skill目录>/scripts/analysis_artifacts.py validate <快照路径>`。只确认文件中的对象列举完整时，可以将该“文件范围”对应 scope 标为 complete；摘要仍说明来源为文件快照。数据库完整性需要实际枚举、权限与分页证据。

完成条件：范围内可读对象有身份、属性和证据；未读对象类型单独标记；快照可解析、可复用。没有实时库不阻止生成离线快照。

## 比较结构

1. 明确哪份是 baseline、哪份是 observed。可以比较两个文件，也可以比较两个环境；文件差异只证明材料不同。schema 改名/环境映射须来自用户或项目事实，记录显式映射后再整理两边的身份，不能任意合并同名对象。
2. 非标准输入先分别生成快照。对齐产品、兼容模式与 identifierPolicy。跨数据库家族或名称规则不明时，先交付不可直接比较的原因和可见差异，不把原始 SQL 文本差异视作生产漂移。
3. 运行 `python3 <skill目录>/scripts/analysis_artifacts.py diff <baseline.json> <observed.json> --out <drift-report.json>`。脚本按对象身份和已知属性精确比较；仅当缺失一侧明确完整覆盖该对象时确认 added/removed。缺失属性、部分枚举、未知身份条件会进入 unknowns。
4. 阅读脚本输出及两边证据，输出简短 drift-report.md，说明新增/移除/属性变化、来源时效、可比范围与待核验。definition 属性的变化先视为定义文本变化；模型读 SQL 判断格式、别名等差异是否有语义影响。对象改名默认表现为移除/新增；仅在有证据时建议可能的对应关系。

完成条件：每条差异可回到两侧材料；空差异与“所有范围相同”分开表达。脚本结构校验成功不证明模型提取准确，关键对象仍需回查原定义。

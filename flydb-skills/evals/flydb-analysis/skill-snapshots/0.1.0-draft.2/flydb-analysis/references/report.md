# 报告约定：flydb-impact-report-v1

默认 Markdown，机器消费者明确需要时再输出同语义 JSON。报告结构按任务规模收缩；一个字段的简单判断不必生成空章节。以下语义保持一致。

## 状态与结论

`analysisStatus` 描述调查进度，不是变更放行状态：

- `completed`：用户明确限定的材料和候选均已处理，可仍有说明过的不可知边界。
- `partial`：已交付有效发现，但用户关心的数据库/代码范围缺失，或受时间、权限、截断限制。
- `blocked`：无法确定变更对象，或没有可分析的材料。说明最小补充要求；已有局部事实仍可附上。

整体不输出 `safe=true` 或审批通过标识。摘要说明哪些地方需要一起处理、哪些结论有条件、什么缺口影响下一步判断。

## 发现与证据

每条发现包含：编号、目标、引用关系、依据级别、具体后果及条件、证据、建议核验或修改的位置。

- `confirmed`：在当前材料中，关系本身有直接证据或完整的可回查链条。例如“该 Mapper 通过 include 引用了目标列”。这不表示生产已运行，也不表示迁移必然失败。
- `inferred`：存在相关线索，但映射、取值或调用链仍有关键缺口。写明假设及如何验证。
- 证据缺失的潜在范围放到 `unknowns`，不伪造一个 confirmed 发现。

一个证据编号可以由多条发现共享。文件证据记录 sourceId、path、起止行与必要摘录；工具证据记录 sourceId、工具/查询范围和结果定位。事实适用于哪个修订/快照由来源记录承担。引用行号需实际读取，不能根据搜索摘要估算。

证据可定位只证明来源存在；关系是否成立还要检查语义。对生产故障、必然失败等断言，需要相应的执行或产品语义证据。

## 覆盖与未知项

每一项覆盖记录明确 `scope`、实际检查内容、状态及限制：

- `inspected`：已处理所列材料及相关候选；不意味着穷尽运行时行为。
- `partial`：该范围仍有未读候选、截断或解析缺口。
- `unavailable`：没有取得该类用户关心的材料。
- `not-applicable`：有项目事实支持该类型不适用，给出理由。

没有证据的类型不要随意判为 not-applicable。若记录文件数，写清枚举规则和分母；不将文件读取比例称为“依赖覆盖率”，也不使用模型主观百分比置信度。

未知项说明缺什么、可能影响哪个结论、最小补充方式。将“没有实时库”“某个外部报表定义未提供”写成可行动的缺口，避免只有一句泛化免责声明。

## Markdown 默认结构

1. 结论摘要：变更、最重要发现和建议下一步。
2. 范围与来源：目标环境、代码修订/脏状态、快照来源与时间、是否实时核验。
3. 影响发现：表格或按调用链分组，标明依据级别与来源。
4. 覆盖与未知项：处理到哪里、剩下什么、会影响哪些判断。
5. 建议动作与复查方式：同步修改位置、需补充的材料、建议验证；未执行动作使用将来式。
6. 分析记录：Skill 版本、宿主及实际可知的模型标识、工具/快照信息；未知模型写 unknown。

重要的排除项可在相关发现附近说明。报告语言跟随用户；专业标识和代码保留原样。

## JSON 最小约定（可选）

需要 JSON 时使用下列字段；它是分析报告，不是迁移 Plan：

| 字段 | 内容 |
|---|---|
| schemaVersion | 固定 `flydb-impact-report-v1` |
| analysisStatus | completed / partial / blocked |
| request | 用户变更及已知目标身份，未知值为 null |
| sources | 具有唯一 id 的材料列表，包含 kind、位置、已知修订/时间、实时性与限制 |
| findings | id、target、claim、basis、impact、conditions、evidenceIds、nextActions |
| evidence | id、sourceId、location、最小 excerpt 或工具结果定位 |
| coverage | scope、status、checked、limitations |
| unknowns | gap、affectedClaims、nextCheck |
| excluded | 被排除的候选、原因及可用证据；无关键排除项时为空数组 |
| provenance | skillVersion、host、model、已使用的工具版本或 unknown |
| sourcePlan | 可选；原样引用提供方、algorithm、id、来源定位，不重算摘要 |

`findings.basis` 使用 confirmed / inferred。数组没有数据时为空数组；无法取得的标量为 null 或明确的 unknown，不能杜撰。证据编号、来源编号须能互相解析。

输出前检查 JSON 可解析、必需字段存在、枚举合法、id 唯一、引用能够解析。宿主可以用已有 JSON 工具完成，首版不要求新运行时。此检查不认证分析语义正确性。

## 继续调查的工作记录

`investigation-notes.md` 记录：变更及范围、来源版本、已核验发现及证据、已排除候选、尚待检查候选、失败/截断情况、下一步。它用于恢复工作，不是数据库审批票据；如果输入变动，标出需要重新核查的条目。

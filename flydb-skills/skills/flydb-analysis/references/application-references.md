# 应用引用

用户可直接问“这个字段哪些地方在用”或要求限定目录内的引用清单，无需提出修改方案。范围很大时先枚举技术栈与分区，再分批交付。

1. 确认实际目标表/列与 schema；用户只给领域属性时从映射反查物理对象，存在歧义则保留候选。记录扫描根、包含/排除目录、修订和未提交状态。
2. 读取 [引用调查](investigation.md) 中实际相关的 MyBatis、JPA、JDBC、SQL 和外部消费段落。搜索物理名称、映射属性、alias、共用片段和构造标识符的常量；逐条读取上下文。
3. MyBatis 追 namespace/statement/interface/caller；JPA 区分属性访问、物理映射、JPQL 与 native SQL；JDBC 追 SQL 来源、参数和结果的按名/序号消费；独立 SQL 文件辨明当前任务入口与历史资料。将可定位的方法、SQL 片段、映射和目标建成 nodes/edges，方向“使用者 → 被使用者”。
4. 输出 task=references 的清单，包含位置、引用链、读写/映射/结果消费类型、confirmed/inferred、未知动态入口和关键排除项。每类材料的实际覆盖单独报告。用户另要影响判断时才继续 [综合影响](impact.md)。

完成条件：找到的重要候选均已确认、推断、排除或列为待核验；返回可直接定位的位置。未提供的外部报表/ETL 只作为具体未知范围，不编造系统、调用关系或生产执行频率。

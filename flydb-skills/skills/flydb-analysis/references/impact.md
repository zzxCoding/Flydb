# 综合变更影响

首版能处理字段删除、改名及定义调整；结论限定在实际材料和可核验的数据库语义。这个流程需要拟议变更，其他流程没有该前置。

1. 记录变更前后对象与定义。用户指定保持 Java 属性/API 等兼容条件时一并记录。类型/长度/精度、可空性、默认值的不同证据需求见 [引用调查](investigation.md)。
2. 按可见材料运行 [数据库依赖](dependencies.md) 和 [应用引用](application-references.md)，共用来源与证据。已有具体 SQL 与产品信息时接续 [方言预检](compatibility.md)；只有自然语言意图时，不为了预检擅自生成并执行迁移。
3. 沿引用链解释需要同步处理的位置及成立条件。物理列改名不自动要求 alias、resultMap 或 Java 属性全部改名。确认引用、确认条件性影响和确认实际故障分别表述；对运行时配置、业务数据与部署状态缺口提出最小核验建议。
4. 输出 task=impact 的报告：最重要影响、同步修改位置、建议验证方式，以及每个相关范围的覆盖与未知项。相同证据去重；可引用已生成的其他分析产物，保留其来源版本和限制。

完成条件：用户给出的变更有对应影响清单；每条重要影响有链路与证据；不可见范围明确。报告提供分析建议，不构成迁移执行或自动修复授权。

# 引用与影响调查

只读取与项目实际技术相关的段落。以下是调查线索，不能替代对当前项目与版本的核验。

## SQL 与数据库对象

先确定表身份，再关联列。核查 SQL 中的 schema、别名、CTE、子查询和同名列；对歧义引用保留候选。注释中的文字和字符串值不直接等于列标识符。

沿视图、过程、触发器、索引和约束定义追查目标。目录依赖可能只到对象级；对象级依赖不能自行细化为某一列的依赖。`SELECT *` 应结合可用结构展开范围，继续核查按列序号读取、结果映射和暴露给下游的字段名。

把“定义里引用目标列”和“该产品执行变更后如何处理对象”分开描述。对象失效、自动更新、禁止变更等行为依赖产品版本与具体语句。

历史迁移用于解释来历；只有它会被当前部署/初始化/回退流程再次执行时，才能将其列为相应运行路径的影响。单独出现同名字符串不足以证明影响。

## MyBatis

由 mapper namespace、statement id、接口方法及调用点建立关系。检查 `sql/include` 共用片段、resultMap、SQL alias、条件分支和注解/Provider，而不只搜索目标字段的字面量。

- `#{...}` 通常是参数绑定，属性名不能直接当作数据库列名；`${...}` 是文本替换，需要核查其实际来源。[Mapper XML 官方说明](https://mybatis.org/mybatis-3/sqlmap-xml.html)
- 检查 `if/choose/foreach` 等分支中是否构造标识符，以及调用方是否限制其取值；动态标签存在不等于全部语句无法分析。[动态 SQL 官方说明](https://mybatis.org/mybatis-3/dynamic-sql.html)
- `${column}` 若来自明确的常量映射，可确认映射里包含的目标；若还接受外部配置或任意参数，应单列无法穷举的入口。
- 字段改名后，SQL alias、resultMap 与 Java 属性可以继续保留旧名。逐层说明需要修改哪里，不要求将所有同名 Java 属性机械改名。

## JPA 与 JDBC

先关联实体表/schema，再查看字段或 getter 上的映射、嵌入/覆盖配置与实际命名策略。仅有 `customerType` 属性不能推定它对应 `CUSTOMER.CUST_TYPE`。

显式 `@Column(name=...)` 提供映射证据；未显式命名时仍要核查项目配置和提供者行为。JPQL 的属性名与 native SQL 的数据库列名分开追查。[Column 官方说明](https://jakarta.ee/specifications/persistence/3.2/apidocs/jakarta.persistence/jakarta/persistence/column)

JDBC 场景关联 SQL 来源、拼接常量和调用者；同时查看按列名/序号读取结果、批处理或导出字段。无法确定 SQL 最终来源时，引用可见拼接路径并记录缺失的配置或调用点。

## 业务与外部消费

追到足以解释影响的服务、任务、导出或接口。已确认服务读取一个实体属性，可以作为调用关系事实；实际业务行为变化应说明触发条件、部署状态与尚未验证的部分。

外部报表、ETL 或配置平台未提供材料时，列为具体未知项。不要为了让报告显得完整而猜测某个系统存在，也不要把仓库内没有找到当作外部没有引用。

## 不同变更需要的补充证据

| 变更 | 优先核查 | 常见缺口 |
|---|---|---|
| 删除列 | SQL/映射、对象定义、结果消费、约束 | 外部任务、SELECT * 消费方、实际启用路径 |
| 重命名列 | 物理列名、alias、映射和构造标识符的位置 | 兼容期、未部署分支、厂商依赖对象行为 |
| 修改类型/长度/精度 | 绑定/读取类型、转换、比较和索引使用 | 数据分布与数据库转换语义 |
| 修改可空性/默认值 | 写入路径、遗漏列的 INSERT、显式 NULL | 存量数据、触发器和应用缺省行为 |

只需要数据分布才能判断的部分应提出最小核验建议；分析任务不自动授权扫描业务表或执行修复。

# 达梦 DM8 实例验证记录（2026-10-21）

## 结论与适用范围

已在用户提供并授权的本地 DM8 8.1.3.62 实例完成只读契约、CLI 校验、预演、首次迁移和重复迁移验证。首次迁移使用原 CLI 0.3.7；第二次运行发现历史表重复初始化缺陷。源码修复后，本地发行包 `0.3.7-local.dm8.20261021` 连续两次零变更迁移成功。

该记录仅覆盖本次版本、驱动及大小写不敏感模式，不代表厂商认证。修复纳入 0.3.8；本页保留最初本地验证包的身份，正式版本获取状态以 [GitHub Releases](https://github.com/zzxCoding/Flydb/releases) 为准。本次未执行 `clean`、`repair`、`baseline`、`undo`，未做并发锁竞争、失败 DDL 恢复、大小写敏感或 `compatibleMode=oracle` 模式的真库验证。迁移能够获取并释放锁，但不能据此宣称并发互斥已实测。

## 缺陷与修复

最小复现为对已存在的专用历史表调用 `SchemaHistory.ensureExists()`。原 JDBC 异常为 `vendorCode=-2124`、`SQLState=22000`，消息为“对象[flydb_dm8_hist_20261021]已存在”；原实现只忽略 Oracle `955`，因此重复运行在准备历史表阶段失败。

修复新增 `SchemaHistoryDdl.isTableAlreadyExists(SQLException)` 默认方法，保留原有 `955` 行为；`DmDatabase` 额外识别 `-2124`。仓储仅调用方言判定，其他建表错误继续上报，不按 `22000` 整体忽略。默认方法保持现有 SPI 实现的兼容性，未新增 core 运行时依赖。设计文档同步说明实际使用的“尝试建表 + 方言异常判定”流程。

回归先于实现添加：原实现 14 项相关测试中 2 项达梦幂等测试报错；修复后通过，并覆盖大小写敏感/不敏感的离线分支、其他同 SQLState 错误不被忽略，以及 Oracle `955` 保持原有行为。大小写敏感分支只有单元测试证据。

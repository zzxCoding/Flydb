# 12 Flydb Web：配置与迁移工作台

状态：设计基线，实施中。用户验收通过前不发布新版本。

本文记录已授权的产品目标、技术决策与验收契约。实现进度和验证证据见
[实施与验收清单](13-web-implementation-plan.md)。已有 CLI、迁移规则和 Plan Artifact
分别继续以设计 05、06、10、11 及 `docs/reference` 为准。

## 1. 产品目标

开发和运维长期管理一套或多套 Flydb 配置。有 Agent 时，Agent 可以编辑原有文件、
调用 CLI，人通过 Web 理解配置、查看变化和观察执行；没有 Agent 时，人能够通过
界面独立完成配置接入、编辑、检查、迁移和故障定位。

优先级为 **易用性第一，美观同样是正式交付要求**。交付必须是可运行、可离线使用、
有实际后端与完整文档的项目，不能以示意页面、模拟进度或仅通过单元测试代替。

**本次只做 GUI。** 不提供用户账户、登录页、角色权限、团队、审批流或授权管理。
打开即进入配置工作台；执行前核对目标是操作确认，不是审批。服务的本机保护属于
实现细节，不增加用户设置步骤。界面主次为配置 → 迁移 → 进度与结果，Agent 是
共用文件和 CLI 的另一种使用方式，不是界面的必需入口。

### 产品边界的调整

原设计 00 排除了必须依赖常驻 REST 服务的迁移方式，ROADMAP 排除了数据库 GUI。
本次明确增加可选的、本机运行的 Flydb 迁移工作台。普通 CLI 不依赖 Web 进程；
Web 复用相同迁移运行时。通用 SQL IDE、数据库对象编辑器、多人审批平台和远程
集群管理仍不在本次交付范围。没有新增或扩张数据库厂商兼容性承诺。

## 2. 用户可见对象

| 对象 | 含义与约束 |
|---|---|
| 配置项（Profile） | 工作台登记的一份配置文件及其执行目录；显示名称、环境标签和分组只用于组织 |
| 配置文档（Configuration document） | 用户、Agent 与 CLI 共用的 UTF-8 Properties 文件；保留其注释、顺序和环境引用 |
| 生效配置（Effective configuration） | 对一次执行解析完配置优先级后的值及来源；包含执行目录，不将文件值冒充最终值 |
| 检查结果（Inspection） | 在明确时间、明确配置修订和目标上取得的状态；可以过期，不等同于实时健康状态 |
| 迁移计划（Plan） | Core 产生的原有 dry-run 结果和 `flydb-plan-v1` 摘要；Web 不计算第二套计划 |
| 执行（Run） | 一次命令实际运行，拥有独立 ID、事件、目标与配置快照和终态 |
| 执行来源（Invocation source） | 可信调用入口声明的 CLI / Web；无法证明由 Agent 发起时不推测 Agent 身份 |

一个配置项不等于一个数据库的永久身份：同一文件可以被环境变量覆盖，因此执行
结果始终关联生效目标和快照。历史记录不随之后的文件编辑或显示名称修改而变动。

## 4. 信息架构与交互

### 4.1 工作台

桌面由窄导航、配置列表和当前配置内容构成。主工作面分为「迁移」「连接与配置」
「执行记录」。单配置直接打开详情；配置列表保留添加入口。多配置支持搜索和分组，记住上次选择。执行中的任务入口始终可见，不因切换配置而失去位置。

显示名称、环境、脱敏后的实际目标在详情顶部保持可见；执行页面显示执行时的
固定目标。环境标签只是便于识别的备注，不代表权限，也不驱动审批规则。

### 4.2 接入和编辑

空状态提供「导入已有配置」「新建配置」。目录发现只遍历用户明确选择的范围，
限制深度/文件数并说明未扫描范围。导入后立即显示文件、工作目录、脚本目录和
凭据来源，未请求检查前不连接所有数据库。

常用数据库使用主机/端口/库名表单；JDBC URL 是可编辑的统一接入口，并支持
厂商特殊 URL。通用字段与高级键值编辑共用同一文档模型，不能相互丢失内容。
新增和已有配置均提供“表单编辑 / 文件编辑”。文件模式使用离线打包的 CodeMirror，
支持行号、Properties 高亮、查找替换、撤销、键补全和快捷保存。模式转换由 Java
Properties 文档模型处理，不在前端重新实现配置语义。注释、顺序、续行和额外键应保留；
语法错误阻止转换或保存，不清除草稿。
新建配置使用共享 InitScaffolder 生成完整模板草稿及落盘；CLI 和 Web 共用目录结构、
默认值和禁止覆盖规则。界面明确列出配置、V1 示例迁移和驱动说明，创建不执行 SQL。
文件模式允许编辑完整模板原文；用户内容在落盘时保持原样。

复制配置要求选择新文件和目标环境，不复制临时密码，不能覆盖已有文件。

保存使用读取时的内容摘要作修订条件，文件锁内再次比较，临时文件与原子替换
完成写入。外部更新提示区分「文件变了」「当前表单有草稿」「正在执行旧快照」。

### 4.3 检查、预演、执行

按现有运行时顺序完成 validate → dry-run → 目标/清单确认 → migrate → info/validate。
检查失败不丢失配置输入。仅在确认阶段集中展示写入影响，避免每步弹无意义确认。

预演确认对象包含配置修订、生效目标、执行目录和 Core 计划摘要。Apply 必须在
共享 Java 执行入口验证确认对象；锁内核对真实待执行集合，并执行已核对的解析
结果。不能用 Web 两次调用之间的比较冒充原子保证。原 `flydb-plan-v1` 算法不变；
新增的目标绑定是独立契约。

迁移进度按实际事件推进；长 SQL 无返回时展示活动心跳和停留时间，确认数保持。
执行成功和结果核验成功独立呈现。关闭浏览器只关闭观察。停止本机后端或操作
系统终止不承诺任务继续，必须保存可恢复证据，不能自动再次提交数据库写入。

## 5. 视觉与双语设计

### 5.1 视觉方向

以 [Flydb 官网](https://flydb.zzxcoding.dev/) 为品牌来源。2026-09-06 已实际打开
首屏，并核对官网源码的色值和品牌标记。此前橄榄绿参考稿已被用户否定，不作为
实现基线。使用深蓝黑底、亮蓝/青色强调、细线边界和官网三瓣标记；浅色主题沿用
官网暖白底。将品牌表现转为适合长时间操作的工具界面，不照搬营销大标题或滚动叙事。

| Token | 深色默认 | 浅色 | 用途 |
|---|---|---|---|
| canvas | `#080b13` | `#f2f0e9` | 页面底色 |
| surface | `#111725` | `#faf9f5` | 编辑和内容表面 |
| primary | `#2867ff` | `#2867ff` | 主要操作和选中 |
| accent | `#42e8ff` | `#006c82` | 活动、品牌和焦点细节 |
| success | `#bff84a` | `#35620e` | 成功状态点，搭配文字 |
| warning | `#ff9f2f` | `#945000` | 需要注意的状态 |

蓝青渐变只用于少量品牌元素。三瓣品牌标记与轻量轨道出现在首次欢迎/空状态；表格、编辑器和执行页
保持清晰静态表面。状态不可用品牌动画模拟；不做无意义指标和层层嵌套的卡片。

- 字体：中英文均使用操作系统无衬线字体；代码使用等宽字体；离线无字体 CDN。
- 正文字号不低于 14px；辅助信息不低于 12px；主要操作高度约 36–40px，触摸目标至少 44px。
- 采用 4px 间距基准、统一圆角与层次；表格按内容分配宽度，长路径能展开/复制。
- 状态同时有文字/图标，不能只靠红绿；焦点可见；普通文字对比度至少 4.5:1。
- 过渡约 120–180ms，避免等待动画妨碍操作；遵守 `prefers-reduced-motion`。
- 1366×768 可完成主要判断并看见主操作；验证 1440、1024、768、390px 和 200% 缩放。

实际页面截图保存在 `docs/design/web/`，覆盖迁移、配置和执行关键视图。以官网品牌和本节 token 为视觉基线，页面截图不代替交互和后端验证。

### 5.2 国际化契约

前端使用 `vue-i18n`，语言为 `zh-CN`、`en`，默认优先已保存偏好，否则匹配浏览器
语言，未匹配时回退英文。首次用户可以明显找到语言切换；切换不清空表单或终止
操作。中英文各有完整键集合，构建检查缺键和无意回退。

后端错误携带稳定 code 和结构化参数，前端提供本地化说明；原始错误放详情。
业务状态 token、API 属性名和计划摘要不翻译。数量、时间、复数和日期通过 locale
格式化。导出报告明确携带语言和时区；原始错误、用户命名、SQL、路径不自动翻译。
CLI 既有中文日志和 stdout schema 不随 Web 语言切换改变。

## 6. 技术选型与模块

| 模块 | 技术与职责 |
|---|---|
| flydb-core | Java 8，无第三方运行时依赖；迁移规则与类型化执行事件；计划核验入口 |
| flydb-runtime（新增） | Java 8；共享 CLI 现有配置、驱动、脚手架、脱敏和结果渲染；配置文档、执行上下文与记录 |
| flydb-cli | Java 8 + picocli；参数和终端交互，调用共享运行时；`web` 启动入口 |
| flydb-web（新增） | Java 8 + JDK HttpServer + Jackson 2.x；本机 HTTP、任务、配置注册和静态资源 |
| flydb-web/frontend | Vue 3 + TypeScript + Vite + vue-i18n；Naive UI 基础控件，统一主题与定制布局 |

依赖方向：CLI → Web / Runtime，Web → Runtime，Runtime → Core。Web 不依赖 CLI
命令类，Core 不知道 HTTP、浏览器、文件记录或国际化库。迁移计划仅由 Core 产生。
Runtime 的持久化序列化依赖可用 Jackson；零依赖承诺仅属于 Core。

选择 JDK HttpServer 是为了保持部署只有 Java 与浏览器。它只承担有界的本机 API；
路由、跨源请求防护、请求体/并发/超时限制、SSE 生命周期必须显式实现和测试。
本次没有用户身份和权限系统，不提供远程多人服务入口。

前端只在开发/发布构建需要 Node.js。发布前执行锁定依赖安装、类型检查、单测及
production build，将静态资源嵌入 Web JAR；运行时不依赖 npm、Vite 服务或外网。
库版本在实现时核实维护状态并锁定，不使用未锁定的 latest。

## 7. 本地存储、事件与运行生命周期

默认状态目录为 `~/.flydb/workbench`，可显式配置到用户有写权限的位置。测试使用
独立临时目录。目录只保存注册信息、偏好及脱敏的执行证据，不保存密码。

- 配置注册使用原子替换与跨进程锁；配置文件仍由用户选择的原位置管理。
- 每次执行独立目录：元数据、追加写事件、终态摘要；每个 Run 单写者。
- 事件含 `schemaVersion`、`runId`、严格递增 `sequence`、时间和事件类型。
- 类型至少覆盖开始、阶段、脚本开始/完成、语句进度、诊断、事务结果、核验、结束。
- 先持久化再通知观察者；临时观察者错误不应打断数据库事务，不能改变迁移语义。
- SSE 提供事件 ID、心跳和断线补发；已保留区间之外先返回快照再继续订阅。
- 区分 RUNNING、SUCCEEDED、FAILED、INTERRUPTED、UNKNOWN；核验另有自己的状态。
- 发现缺失终态的陈旧 Run 时，核对进程持有的运行锁；锁仍持有表示还在运行，
  不因心跳超时推断进程死亡。无人持有且无终态时标为 UNKNOWN，不自动重放。
- 记录关联执行时的配置与目标，明确属于哪一状态目录；不宣称自动观察远程机器。

CLI 的 `--json` stdout 保持一行。实时事件通过记录层传递，不混入 stdout；现有
stderr 日志保持人类可读。记录位置不可写必须给出明确状态，不谎报已留存证据。

## 8. 本机服务实现约束（无用户管理界面）

- 只监听回环地址；默认使用空闲端口，支持显式端口；不提供外网监听参数。
- 普通本机地址在新浏览器中也能直接打开。页面通过严格同源、JSON POST 自动建立
  HttpOnly、SameSite=Strict 临时 Cookie；该启动请求必须携带与服务完全一致的 Origin，
  缺失或跨源均拒绝。保留启动 URL fragment 的兼容交换方式，页面连接成功后清除 fragment。
  浏览器自动完成，不出现登录、授权或令牌管理页面。凭证不进查询字符串、持久化和报告。
- 校验 Host、Origin 和请求 Content-Type；拒绝跨源写入；不开放通配 CORS。
- GET 不产生配置、目录、数据库等写入；API 和 SSE 校验浏览器自动携带的本机凭证。
- 文件选择直接使用运行 CLI 的操作系统用户可访问的路径，不新增目录授权配置。
  浏览/发现有界，只返回选取配置所需的信息；已登记配置的操作按固定 ID 定位，
  不暴露通用文件下载、命令执行或任意 SQL 执行 API。
- 普通配置快照、执行证据和报告继续脱敏，不返回明文密码。用户主动打开“文件编辑”时，
  专用文档接口按其编辑请求返回原文件内容（可能包含原文件中的明文凭据），仅在当前
  页面内存中维护草稿，不写入浏览器存储、执行记录或日志。此例外不适用于运行 API。
  环境变量和密码文件的实际值不会由文档转换接口解析或展示。
- 同一运行上下文的写入提交去重；数据库并发安全继续由 Core 迁移锁负责。

## 9. 验证和交付

验证必须覆盖真实 HTTP、文件保存/外部编辑、SSE 补发、并发与幂等、密码脱敏、CLI
和 GUI 交叉观察、进程异常终态，以及真实发行包中的静态资源和启动入口。

使用获授权的本地临时测试数据库做端到端迁移，不连接用户已有数据库；复用已有
MySQL/PostgreSQL CI 契约范围。厂商数据库若没有实库证据，仍明确标为未执行。

交付包含：源码、设计文档、中文/英文使用指南、配置/HTTP/事件参考、测试与视觉
验收记录、可本地启动的候选 ZIP。用户验收前不推送 release tag、不发布 GitHub
Release、不部署到 Maven Central/npm。最终发布是单独步骤。

## 10. 选型依据
